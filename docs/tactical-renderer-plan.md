# 甲、第二級完整版

## 1. 目標與不做的事

要達到的：

- **流暢**：個體移動、轉向、姿勢、瞄準、倒地都有連續過渡；鏡頭平移、縮放不閃爍、不頓；播放速度穩定，不因伺服器抖動忽快忽慢。
- **看得懂**：不看圖例也分得出我方、友軍、敵人（確認）、最後已知、聽到的槍聲；看得出誰在動、誰在掩護、誰被壓制、誰倒了、誰在救誰；看得出小隊正在執行什麼戰術、要去哪裡、命令執行到哪。
- **有交火的感覺**：槍口火光、曳光、彈著、手榴彈拋物線、爆炸、有體積的煙霧，加上依距離與方向的槍聲、爆炸聲、無線電提示音。
- **看得到自己的視野**：我方實際看得到哪裡（伺服器用和偵測相同的視線算），其他地方調暗。
- **不漏重要的事**：落後、切分頁、多場交火同時進行時，傷亡、命令結果、情報變化都不會被略過。

不做的（留給第三級）：

- 角色 sprite、骨架動畫、頭像、事件特寫、配樂、無線電語音。
- 手工繪製的地標與場景物件。

始終不做的：

- 單兵微操、新的命令種類。
- 改變模擬結果。前端不決定任何命中、發現、傷亡（[interface.md §1](interface.md#1-原則)）；後端新增的呈現資料只是把已經算出來的東西送出來，**固定遭遇摘要必須不變**。

## 2. 現在的問題（要解決的）

| 問題 | 原因（目前程式） | 本方案的對應 |
|---|---|---|
| 高 DPI 螢幕整張糊 | canvas 以 CSS 像素建立，沒有處理 `devicePixelRatio` | Pixi `resolution` 跟著 DPR（§7） |
| 鏡頭移動時牆和格線閃爍 | 8 px／格的離屏圖用最近點縮放，倍率非整數、相機座標是小數 | 地形依縮放級距重新烘焙、平移時對齊像素（§7.1） |
| 鏡頭頓、各電腦手感不同 | 跟隨每畫一次移 0.12，跟更新率綁在一起；縮放瞬間跳、不以滑鼠為中心 | 時間制緩動、以游標為中心平滑縮放（§9） |
| 播放忽快忽慢 | 每格播放長度跟著收到影格的間隔（`playMs`）、佇列再加速 | 單一戰鬥時鐘＋緩衝控制（§5） |
| 等不到影格就停住、之後跳一下 | 影格播完進度卡在 1，`nx` 最多推到 95% | 個體軌跡跨影格取樣（§5.3） |
| 轉向、姿勢、倒地、敵人出現都是瞬間 | 直接用影格結束時的值畫 | 後端送變化時間（§6）＋前端過渡（§7.2） |
| 交火沒節奏 | 子彈是一整條直線、畫 0.3 秒；爆炸是一個圓；沒有聲音 | 特效層（§7.3）、音效（§8） |
| 看不出小隊在做什麼 | 畫面只有個體，戰術意圖、目標、誰掩護誰前進都只在文字裡 | 小隊意圖層（§7.5） |
| 畫面簡陋 | 地形是色塊、沒有地面材質，單位是圓點加一條線 | 程式化視覺語言（§7） |

## 3. 技術選型

- **PixiJS v8**（WebGL）。Phaser 帶的 scene 與 loader 用不到；音效自己用 Web Audio 做（§8），不需要 Phaser 的 audio。
- **TypeScript + Vite**：這次是長期的前端，要做到好就值得建置流程。
  - 型別：伺服器送來的影格、事件、視圖有明確型別（`protocol.ts`），欄位改了會在編譯時發現。
  - 測試：純邏輯模組（時鐘、軌跡、視野合成、音效排程）用 **Vitest** 跑，不需要瀏覽器。`scripts/run_tests.py` 在本機有 Node 時一併執行，沒有就略過並提示。
  - 開發：Vite dev server 代理 `/api`、`/ws` 到 aiohttp，改了前端立即更新。
  - 部署：`npm run build` 產出 `web/static/dist/`，由 aiohttp 提供；伺服器執行時不跑 Node，只有建置時要用。`dist/` 不進 git（§14）。
- 新前端只負責戰術圖；指揮室其他面板仍是現在的 `app.js`，透過 §4 的介面互動。之後要不要把其他面板也搬進 TS，另外決定。
- 文字密集的部分（工具列、選取卡、戰鬥紀錄、圖例）用 HTML/CSS 疊在畫布上。

新目錄 `web/tac/`（原始碼，TS）→ 建置到 `web/static/dist/`：

對外介面（取代 `drawWorld`、`currentUnits` 等，掛在 `window.Tac` 給 `app.js` 用）：

```ts

Tac.setTerrain(worldTerrain)     // /api/world_terrain
Tac.pushView(world)              // /api/world 或 WebSocket 推送的畫面（含 frames）
```

原則（沿用舊方案 §5.3）：renderer 不解析業務規則；網路層不碰圖形物件；前端不推測未知敵人的位置。
**個體表現層要可替換**：`units.ts` 透過一個「個體外觀」介面畫（給它取樣出的狀態，它決定怎麼畫）。第二級實作「符號」與「機兵剪影」兩種，第三級加「sprite／骨架」一種，其他模組不用改。

## 5. 播放：單一戰鬥時鐘

流暢感的核心，最先做。

### 5.1 時鐘

- 整個畫面只有一個「現在播到的戰鬥時間」`bt`，每幀依實際經過時間前進：`bt += dt × rate`。
- 收到的影格帶 `ts0～ts1`。目標是讓 `bt` 落後最新的 `ts1` 一段固定緩衝 `D`（預設 0.75 秒，約 1.5 個執行步）。
- `rate` 依緩衝量微調，不直接跳：緩衝 > D 時最多 1.1 倍、< D 時最少 0.9 倍，以低通平滑（時間常數約 2 秒）。伺服器穩定時 `rate` 收斂到 1.0。
- 緩衝見底（`bt` 追到最新的 `ts1`）：時鐘停住，個體依 §5.3 處理，**不倒退**。
- 落後超過 3 秒（分頁在背景、斷線重連）：直接跳到 `ts1 − D`。中間過期的子彈與粒子不補播，但**傷亡、命令結果、情報變化**照樣進入 §10 的注意力佇列與戰鬥紀錄，倒地與陣亡記號照樣出現。
- 伺服器整體變慢（時間倍率 < 1，頂部顯示 ⏱）：影格本身涵蓋的戰鬥時間就變慢，時鐘不用特別處理。
- 回放：`rate` ＝ 播放速度，可暫停、拖曳；不用緩衝控制。

和現在的差別：現在是「每格影格各自一段播放長度」，收到的間隔一抖，整格就變快變慢。改成一個連續時鐘後，抖動只影響緩衝量，畫面速度不變。

### 5.2 個體軌跡與事件時間軸

- 每個個體保留一條時間軌跡：`[(t, x, y, z), …]`，由影格的 `from`、`path`、`pt`（抵達）、`pst`（起步）組成，跨影格接起來；保留最近約 10 秒。
- 姿勢、朝向、瞄準、架槍、壓制、倒地等狀態也記成「在某個時間變成某個值」，時間來自 §6 的後端呈現資料；倒地取打倒他那一槍的 `down` 事件 `ts`。
- 子彈（`shots[].ts`）、爆炸（`blasts[].ts`）、投擲（`ev` 的 `throw`，有 `frm`、`at`）、結構化事件全部放進一個依 `ts` 排序的時間軸；以 `seq` 去重，重送或重連不會播兩次。
- 取樣：`sample(bt)` 回傳那一刻每個個體的位置、朝向、姿勢、狀態，以及「這一刻該觸發的特效與聲音」。renderer 和 audio 只用取樣結果。
- 回放拖曳時間：從最近的檢查點（每 30 秒存一個）重建到目標時間。

### 5.3 移動內插

- 兩格之間：依 `pst`→`pt` 的時間內插，起步、停下各約 0.15 秒的加減速，中間等速。
- 轉角圓滑：連續幾格的路徑做圓角（半徑最多 0.35 格）。**限制**：只在相關格子都是可站立的空地時才做，不讓人看起來穿過牆角或離開掩體。
- 緩衝見底時：有 `nx`（正在走向的下一格）就照預計抵達時間 `nt` 繼續走到那一格、在那裡停住；伺服器確認後位置一致，不會跳。沒有 `nx` 就停住。
- 伺服器修正（新影格的位置與目前畫的差超過 0.3 格）：0.2 秒內滑過去；差超過 3 格（重生、整補換人）才直接跳。

## 6. 後端呈現資料

這一級正式納入後端改動。原則：**只送引擎已經算出來的東西**，不改任何規則與亂數；每一項都經過迷霧過濾（[interface.md §3](interface.md#3-結構化事件與迷霧過濾)）；加完跑全部離線測試與固定遭遇摘要，摘要必須不變。

| 資料 | 內容 | 用途 | 迷霧規則 |
|---|---|---|---|
| **瞄準** | 射擊動作開始時送 `aim` 事件（`ts`、目標方向，瞄準時間來自 `timeline.aim_time`） | 「舉槍、轉向目標 → 開火」，射擊方向在開火前就看得出來 | 看不到的敵人不送 |
| **轉向與姿勢時間** | 朝向、姿勢改變的時間（現在只有影格結束時的值）；路徑每格附當時朝向（配合邊走邊面向威脅） | 轉身、蹲下、臥倒在正確的時間發生 | 同個體可見性 |
| **我方視野** | 每次完整感知（每秒一次）時，為玩家與友軍的每個個體算一個視野多邊形（例如 64 條射線，用和偵測相同的視線函式、眼高與距離上限，煙霧也算），簡化後送出 | §7.4 視野遮罩，準確而不是近似 | 只送給該指揮官自己與友軍的單位 |
| **小隊意圖** | 每個小隊目前的戰術意圖（`Intent.kind`、`goal`、`side`、`focus`）、交互掩護的分組（`bounding_plans` 的前進組／掩護組）、破門的目標房間 | §7.5 小隊意圖層 | 只送自己的小隊與友軍；敵方意圖不送 |
| **命令狀態** | 命令的生命週期：送出 → 隊長收到 → 解讀成什麼 → 執行中 → 完成／中斷（原因）。和 TODO 的「命令生命週期顯示」是同一件事 | 地圖上標出命令執行到哪 | 只給下令的指揮官 |
| **地面層** | `world_terrain` 加每格地面類型：依 `mapgen` 的格子模板（街道、路口、瓦礫空地、田野、公園、貨櫃區……）與建築內外 | §7.1 地面材質 | 地形本來就公開 |
| **彈著材質** | 子彈打到什麼（牆、矮牆、地面、植被、人），現在只有 `kind` | 彈著特效與聲音依材質不同 | 照現在子彈的過濾 |

效能預算：視野多邊形每秒一次、只算玩家與友軍的單位（四位指揮官約 20～30 人），目標 ≤ 15 ms／秒；S4 前用 `sim_bench.py` 實測，超過就降低射線數或只算移動過的人。

## 7. 視覺語言

整體方向：**深色戰術圖**，有層次、光影和動態；不用照片質感，全部用程式畫。色調見 §14。

圖層由下往上：地面 → 地面裝飾（瓦礫、植被底層）→ 矮牆 → 地面特效（彈著、焦痕、血跡）→ 小隊意圖（路線、目標）→ 個體 → 牆與窗 → 植被樹冠 → 煙霧 → 空中特效（曳光、拋物線、爆炸）→ 視野遮罩 → 區域外調暗、格界 → 標記與情報 → 標籤 → 工具預覽。
牆畫在個體上面（有高度感），個體在牆後時以半透明輪廓顯示，不會被蓋住看不到。

### 7.1 地形

- **地面**：依地面層分材質：柏油（街道、路口，帶淡淡的車道線）、碎石（瓦礫空地）、草地（田野、公園）、水泥（貨櫃區、廠房外）；材質用程式雜訊產生，深色、低對比，不搶個體的注意力。建築內地板較亮一階，看得出室內外。
- **牆**（`#`、`|`）：實心、上緣亮邊、往一個固定方向投短陰影；相鄰牆格合併成連續的牆，不是一格一格的方塊；牆角有細小的破損缺口（依座標決定，不閃）。
- **窗**（`W`）：牆上一段淺藍細線，表示「可以看出去、可以射擊」。
- **門**：牆上的缺口加門框色。
- **矮牆**（`=`）：較低、較細、陰影較短。
- **瓦礫**（`%`）：幾個不規則碎塊。**植被**（`"`）：分底層與樹冠兩層，樹冠半透明、邊緣柔和，在個體上面。
- **樓梯**（`H`）：階梯紋；有二樓的建築（目前只有中繼塔）畫出平台外框。
- **地標**：有名字的格子（中繼塔、醫院廢墟……）在戰況級距顯示名稱與簡單的程式圖示。
- **格界**：作戰格（5×5 大格）的邊界保留、細線；2 m 小格的格線只在個體級距淡淡出現。
- 實作：依縮放級距（每格 8／16／32 px）把地形烘成 512 px 的分塊貼圖，跨級距時才重烘，平移時對齊整數像素。

### 7.2 個體

兩種外觀，依縮放自動切換（也可在圖層開關固定其中一種）：

- **符號**（戰況、小隊級距）：抽象、最好讀。
- **機兵剪影**（個體級距）：程式畫的俯視機兵：頭部感測器、肩甲、身體、手中武器（依 `weapon` 分步槍、機槍、射手步槍等不同長度與形狀），姿勢與動作有簡單的骨架動畫（走路時肩膀擺動、臥姿時身體拉長、射擊時後座）。設定上部隊是生化人／機器人，這種造型可以全用幾何形狀畫，不需要美術資產。

辨識**不只靠顏色**（色覺差異），陣營同時用形狀區分：

| 對象 | 符號 | 剪影 | 顏色 |
|---|---|---|---|
| 我方 | 圓形身體＋朝向楔形 | 圓肩 | 綠 |
| 友軍 | 圓角方形＋朝向楔形 | 方肩 | 青 |
| 殘部 | 圓形、外圈虛線 | 圓肩、虛線外框 | 淺青 |
| 敵人（看得到） | 菱形＋朝向楔形 | 尖肩 | 紅 |
| 敵人最後已知 | 空心虛線菱形，隨時間變淡，旁邊秒數 | 同符號 | 紅 |
| 聽到的槍聲 | 誤差圈＋「?」，大小照引擎給的誤差 | 同符號 | 琥珀 |

- **朝向**：身體前方的楔形與槍線，約 0.15 秒轉過去（最短方向）；轉向時間照 §6。
- **瞄準**：`aim` 事件開始，槍線轉向目標並微微延長，開火時回縮（後座）。
- **姿勢**：站、蹲（縮小、加一道橫紋）、臥（沿朝向拉長），約 0.25 秒過渡。
- **狀態**：
  - 被壓制：琥珀外圈輕微抖動，剪影時身體壓低；釘死：紅色外圈加粗。
  - 架槍：槍線前端加兩腳架記號；架槍中：記號閃爍。
  - 光學過載：白色虛線圈，剪影的感測器變白。
  - 倒地：倒成臥姿、顏色變暗、旁邊傷員記號；已穩定變十字；被拖行時有一條連到拖人者的線。
  - 急救：救援者與傷員之間一條細線＋進度環。
  - 在 2 樓以上（`pos[2]`）：白框加「2F」，畫在上層。
- **移動中**：腳下短拖尾，衝刺時較長；剪影有步伐擺動。
- **出現與消失**：敵人被發現時 0.2 秒淡入，失去目標時淡出並在原地留下最後已知記號；陣亡 0.5 秒倒下淡出，留下記號 30 秒。
- **標籤**：名字只在小隊級距以上顯示，自動避開重疊；行動理由（`why`）在選取或個體級距顯示。
- **選取**：外圈＋最近幾秒走過的路徑淡線＋（我方）理由標籤。

### 7.3 特效

所有特效都在自己的 `ts` 觸發；看不到的射手照迷霧規則只畫彈道後段（伺服器已經裁好）。

- **射擊**：槍口火光（約 0.05 秒，附近地面短暫被照亮）→ 曳光段沿彈道飛過去（視覺速度約 150 m/s，看得出方向）→ 彈著。
  - 連發時曳光每 2 發畫 1 發，避免一整片亮線蓋住畫面（可讀性的選擇，聲音照實際發數）。
  - 彈著依材質（§6）：牆是灰白粉塵與碎屑，地面是土花，植被是葉片，命中是短暫紅點（只有看得到目標時）。
  - 壓制射擊：較細、較淡的曳光，兩波。警戒射擊：青色曳光（延續目前的語彙）。
- **投擲**：從 `throw` 的 `frm` 到 `at` 畫一條拋物線飛行物（有陰影），在 `blast` 的 `ts` 爆炸。
- **爆炸**：一閃 → 擴散的衝擊環 → 碎屑粒子 → 地面焦痕約 60 秒。閃光彈：大範圍白閃，沒有碎屑。
- **煙霧**：粒子雲，濃度（`density`）決定不透明度，緩慢飄動；邊緣柔和，不暗示比引擎更精確的形狀。
- **畫面震動**：只在附近有爆炸、而且有我方在附近時，幅度小，可關閉。
- **粒子上限**：全畫面約 3000 個，超過就丟最舊的；分頁在背景時不產生。

### 7.4 視野遮罩

- 用伺服器送的視野多邊形（§6），把玩家與友軍的視野合起來；視野外調暗約 40%，邊緣柔和。
- 每秒更新一次；兩次之間依個體移動平移多邊形，下一次到時漸變過去，不跳。
- 這和引擎的偵測用同一套視線，所以「暗處沒看到敵人」是真的沒看到；但偵測還看姿勢、距離衰減、壓制，**視野內不代表一定會發現**，說明裡寫清楚。
- 圖層開關預設開。

### 7.5 小隊意圖層

這是指揮官視角最重要的一層：**看的是小隊在做什麼，不是每個人在哪裡**。

- 每個自己的小隊（與友軍，較淡）：
  - 目前戰術以圖示加短文字標在小隊旁：壓制推進、包抄（左／右）、伏擊、突擊、破門、撤退、固守、行軍。
  - 目標：行軍與推進畫路線到目標點；包抄畫一道繞向側翼的弧形箭頭；破門標出目標房間；撤退標出撤退方向；集火點畫準星。
  - 交互掩護：前進組與掩護組用不同的地面圈標示，掩護組朝向壓制方向畫一個淡扇形。「誰在掩護誰在動」一眼看得出來。
- **命令狀態**：下令後，小隊旁出現命令標籤，依 §6 的生命週期變化：送出（灰）→ 收到（白）→ 執行中（綠，顯示解讀結果，例如「→ 包抄左翼」）→ 完成或中斷（中斷顯示原因，例如「遇敵、改固守」）；數秒後收起，點小隊可以再看。
- 戰況級距：每個小隊縮成一個合併符號（中心、人數／可作戰人數、狀態色、戰術圖示），意圖箭頭保留。

### 7.6 其他 overlay

- 活動區域外調暗（照現在），交戰中的格子邊框緩慢呼吸。
- 作戰層情報（區域外的「!3」「?2」）：帶外框的標記，越舊越淡。
- 標定點（集結、包抄、集火）：地上的旗標、箭頭、準星，連一條虛線到該小隊。
- 支援：
  - 預告：落點準星＋倒數環（照 `eta` 縮小）。
  - 無人機作用中：16 m 掃描圈緩慢旋轉。
  - 空投：降落傘從上方落下，`eta` 落地後是箱子。
- 跟隨的小隊在畫面外時，邊緣箭頭（照現在）。

## 8. 音效

第二級就做，因為「交火有節奏」一半靠聲音。素材用可商用的免費音效（CC0 等，來源與授權記在 `web/tac/assets/README.md`）；第三級再換成正式音效。

- **優先順序**（沿用 [interface.md §4](interface.md#4-呈現路線之後)）：無線電提示 → 槍聲、爆炸 → 壓制、受傷、急救提示 → 環境底噪 → UI。
- **空間化**：以鏡頭中心為聽者，依距離衰減音量、依左右方向聲道平移；遠處的槍聲加低通濾波，聽起來悶。
- **依武器**：步槍、機槍、射手步槍、手槍不同聲音；壓制射擊是連發。
- **情報精度**：看不到的射手只用「聽到槍聲」事件給的誤差位置定方向；音效精度不超過情報精度。
- **上限**：同時最多約 12 個聲音，同一射手的連發合併；分頁在背景時靜音。
- **無線電**：小隊回報、命令回執、緊急呼叫各一種提示音（不是語音）。
- 音量總開關、分類音量、預設不自動播放（瀏覽器規定要使用者先互動一次）。

## 9. 相機

- 跟隨：每幀 `cam += (target − cam) × (1 − e^(−dt/τ))`，τ ≈ 0.25 秒，跟更新率無關；目標是小隊中可行動者的中心。
- 縮放：滾輪以游標位置為中心，平滑過去（τ ≈ 0.12 秒），範圍沿用 3～40 px／格；觸控板雙指縮放也支援。
- 拖曳：照現在，拖了就取消跟隨；🎯 回到跟隨。
- 三個縮放級距（對應 [interface.md §4](interface.md#4-呈現路線之後) 的資訊層級）：
  - **戰況**（< 6 px／格）：小隊合併符號、意圖箭頭、交火區塊、傷亡記號；不畫個體與曳光。
  - **小隊**（6～16）：個體符號、曳光、名字、意圖層。
  - **個體**（> 16）：機兵剪影、小格格線、行動理由、瞄準、壓制與架槍細節。
- 不自動搶鏡頭；事件提示見 §10。

## 10. 注意力與事件

- **重要事件佇列**（`attention.ts`）：接敵、我方首次傷亡、陣亡、命令中斷、救援完成、支援到達、敵人在新方向出現。
  - 每件在畫面邊緣出現提示卡（「⚔ Bravo 接敵（東北）→ 查看」），點了鏡頭平滑移過去、短暫暫停跟隨；不點 6 秒後收起，留在事件列。
  - 事件發生在畫面外：邊緣顯示方向指示。
- **多場交火**：上方列顯示目前所有交火格，點了切過去；不自動來回跳。
- 落後跳過時（§5.1），被跳過的重要事件照樣進佇列，標示「剛才」。

## 11. 互動與 HUD

都是疊在畫布上的 HTML：

- **上方列**：活動區域、交火格清單、時間倍率、跟隨／縮放按鈕、圖層開關（視野、意圖、射線、理由、名字、格線、外觀：自動／符號／剪影）、音量。
- **工具列**：標定（集結、包抄、集火）與支援（空投、煙幕、無人機），按鈕加大、附快捷鍵 `1`～`6`，`Esc` 取消；小隊選擇沿用，`Tab` 切換小隊。
- **放置預覽**：游標位置畫出效果範圍：無人機 16 m 圈、空投散布圈、煙牆方向；集結、包抄畫出從小隊中心過去的預計路線。
- **懸停提示**：名字、姿勢、正在做什麼；最後已知顯示「N 秒前」。
- **選取卡**：照現在 `renderTacUnit` 的內容，浮在畫面角落；選小隊時顯示小隊意圖與命令狀態。
- **時間列**：到下一個作戰 tick，加上播放落後幾秒（落後 > 1.5 秒才顯示）。
- **圖例**：收進 `?`，用實際畫出來的符號當圖例。
- **診斷**（`F3`）：fps、幀時間、緩衝量、時鐘倍率、粒子數、聲音數、個體數、payload 大小。
- 戰鬥紀錄維持在畫布下方的 HTML（現在的同步與節流照舊），點紀錄可以跳到那個人。

## 12. 回放

- 同一個 renderer、同一套時鐘（§5.1 回放模式）、同一套音效。
- 時間軸可拖曳；上面標出倒地、陣亡、爆炸、支援、命令、戰術改變的時間點，點了跳過去。
- 速度 0.25／0.5／1／2／4 倍、暫停、逐步（一次 0.5 秒）。
- 回放紀錄要包含 §6 的新資料（視野、意圖、命令狀態）；舊回放沒有這些資料時，對應的層不顯示。
- **戰後摘要**：回放開頭一張卡，列出誰被誰打倒、誰救了誰、用了哪些支援，每一條都能跳到那個時間。資料來自結構化事件，和 TODO 的 AAR 是同一件事。

## 13. 效能預算

- 目標裝置：一般筆電內顯，1920×1080、DPR 1.25～1.5。
- 120 個個體、交火中：維持 55 fps 以上，單幀不超過 33 ms。
- 每幀 JS 工作（取樣＋各層更新）≤ 4 ms；音效排程 ≤ 0.5 ms。
- 地形分塊只在縮放跨級距時重烘；文字用 BitmapText 或快取。
- 推送量：§6 新資料加上後，每個執行步的推送大小增加不超過 30%（視野多邊形每秒一次、意圖有變才送）。
- 不支援 WebGL：顯示提示；轉換期間退回舊的 Canvas renderer（§15 的開關）。

## 14. 決定事項

已決定：

1. **`dist/` 不進 git**：另外寫 `scripts/build_web.py`；伺服器啟動時找不到 `dist/` 就退回舊畫面並在 log 提示。跑伺服器的機器要有 Node。
2. **只支援連續地圖**：舊的單格戰術畫面（`zone_mode` 關閉時）不移植，繼續用舊畫面。
3. **個體級距預設外觀：機兵剪影**，符號當開關。
4. **音效先用免費素材**（CC0 優先），來源與授權記在 `web/tac/assets/README.md`。

還沒決定：

- **色調**：延續現在的綠色指揮室風格，還是改成中性的灰藍戰術圖（綠色地圖上我方綠色單位的對比較差）？S2 開始時用同一場戰鬥各做一版截圖比較再定。

# 乙、第三級評估

## 17. 第三級加什麼

在第二級（可替換的個體外觀、音效系統、注意力系統都已就位）之上：

1. **戰場角色**：sprite 或骨架動畫，取代程式畫的機兵剪影。動作：待命（站、蹲、臥）、走、跑、匍匐、瞄準與射擊（三種姿勢）、投擲、急救、拖行、倒地、陣亡、破門。
2. **頭像**：用在無線電、命令回執、事件提示、戰後摘要；依可驗證的狀態換表情（中性、緊張、受傷、堅定），不由 LLM 決定（[interface.md §5](interface.md#5-角色呈現phase-4沒有固定美術能力的前提)）。
3. **事件特寫**（選配、可關）：首次傷亡、破門、隊長陣亡時，畫面角落出現短暫的特寫卡。
4. **正式音效與配樂**：正式槍聲、環境音、依交戰強度變化的配樂。
5. **地標與場景物件**：中繼塔、醫院廢墟、地鐵站等手工物件，讓每個區域有記憶點。
6. **（選配）無線電語音**：隊長回報用 TTS 念出來。

## 18. 能達到的效果

- **角色存在感**：玩家會記得「K-07 在中繼塔下面被打倒、R-12 把他拖回來」，而不是「一個綠點變成 X」。這是遊戲在情感上的主要來源；目前這部分全靠文字，第二級也只能靠名字標籤。
- **動作可讀性再上一層**：瞄準、投擲、急救、拖行有實際動作，不需要靠線條和進度環解釋。
- **畫面像一個產品**：能拿來做宣傳截圖、影片，第二級的程式化畫面在這點上有明顯的天花板。
- **無線電變成「人在說話」**：頭像加表情，再加上選配的語音，指揮官「透過通訊指揮」的核心體驗會強很多。

**做不到、或不會變好的**：

- 戰術可讀性主要由第二級決定。第三級的角色在遠距離反而比符號難讀，所以戰況、小隊級距仍然用符號。
- 動畫精度受模擬資料限制：沒有模擬的動作（換彈、掩體內探頭）畫不出來；要畫就得先在模擬裡加這些動作，那是戰鬥規則的改動，不只是呈現。
- 2 m 一格、8 方向朝向的模擬精度，限制了動畫能多細；俯視角下影響不大，換成斜角或 3D 就會很明顯。

## 19. 前提與關鍵決定

第三級**不能直接開工**，要先回答 [open-questions.md「介面與美術」](open-questions.md#介面與美術) 的幾題，其中三題決定成本的量級：

1. **視角：俯視還是斜角（2.5D）？**
   - **俯視**：一套動作可以直接旋轉成任何方向，**不需要分方向畫**。成本最低，也和第二級的畫面、2 m 格子的模擬最一致。
   - **斜角**：每個動作要畫 4 或 8 個方向，資產量是俯視的 4～8 倍，牆的遮擋、深度排序也複雜得多。
   - **建議俯視**。
2. **sprite 還是骨架動畫？**
   - 骨架（Spine 或 DragonBones）：一套骨架共用所有動作，換零件就變不同角色；檔案小、動作平順。Spine 要付授權費（金額以官方為準），DragonBones 免費但維護較少。
   - 逐格 sprite：每個角色、每個動作都要畫，數量會很大。
   - **建議骨架**，和下一點的模組化搭配。
3. **角色怎麼取得？**
   - 這個專案的角色多數是生成的：開局小隊只有隊長有完整人格與角色卡，其他是白紙兵，之後還有預備兵池、殘部、俘獲重編。**不可能每個角色都委託美術**。
   - 設定是生化人／機器人，這反而是優勢：做一套**模組化零件**（頭部、感測器、肩甲、身體、武器、塗裝、編號貼花，各幾種），依個體的種子組合，每個白紙兵都不一樣；受損可以直接畫成零件缺損，比人類角色好處理。
   - 頭像同理：分層零件組合成頭像，表情用感測器的光、面罩顯示的圖示表現，不需要畫人臉表情。
   - 只有有角色卡的代表角色（2～4 名）委託專屬頭像與塗裝。

其他待決定：美術基調（可愛、戰術、壓抑）、比例、要對標的三個遊戲、資產來源（商店素材、委託、混合）、AI 生成是否只限內部概念階段。

## 20. 工作量

假設：俯視、骨架動畫、模組化機兵、2～4 名代表角色。

| 項目 | 資產 | 程式 |
|---|---|---|
| 美術方向 | 風格稿、色票、2 名代表角色的定稿 | — |
| 戰場角色 | 1 套骨架 × 約 15 個動作；零件 4～6 類 × 每類 3～5 種；3 種武器 | 動作狀態機（模擬狀態與事件 → 動作）、零件組合、受損表現、依縮放切換到符號 |
| 頭像 | 分層零件一套＋代表角色專屬頭像 2～4 張 × 4 種表情 | 頭像組合、表情由狀態觸發、接進無線電與事件欄（這部分在戰術圖以外，要動 `app.js`） |
| 事件特寫 | 3～4 種特寫卡版型 | 觸發規則、冷卻、可關閉 |
| 音效與配樂 | 正式槍聲與爆炸各武器數種、環境音每種地形一組、配樂 2～3 段可疊加 | 依交戰強度混音 |
| 地標 | 每個有名字的地標 1 組物件（目前約 10 個） | 擺放與遮擋 |
| 無線電語音（選配） | — | TTS 服務串接、成本控制、延遲處理 |

程式部分約 **6～8 週**（第二級完成之後）。資產的時間與費用**取決於取得方式**，要拿到報價才能估：委託的話，等待與修改往往比程式還久；商店素材比較快，但要找到風格一致、有機兵、俯視角度的素材不容易。

整體估計：第二級 10～11 週之後，第三級再 **3～6 個月**，大部分是資產取得與風格修改的時間。

## 21. 風險

| 風險 | 說明 | 控制 |
|---|---|---|
| 美術方向反覆 | 沒有固定的美術能力，風格容易一改再改，已經做的資產作廢 | 先用 2 名代表角色定稿，再擴大 |
| 可讀性倒退 | 精緻的角色在遠處比符號難讀，敵我分辨變差 | 戰況、小隊級距仍用符號；每次加資產都重做理解度測試 |
| 動畫和模擬不同步 | 動作需要的時間資料（瞄準、投擲出手、急救開始）不完整，動作會對不上 | 第二級的 §6 先把呈現資料補齊 |
| 成本 | 委託與授權費用、TTS 的使用費 | 每一項都先做小規模驗證再擴大 |
| 一致性 | 商店素材、委託、程式畫的東西混在一起風格不搭 | 第二級的程式化視覺就先定好色票與線條規則，資產照著做 |

## 22. 建議

1. **先把第二級完整做完**，而且一開始就照第三級的需要設計：個體外觀可替換（§4）、呈現資料齊全（§6）、音效系統（§8）、注意力系統（§10）。第三級只是換外觀與資產，不用再重寫。
2. 第二級做到 S4 左右，同時開始第三級的**前置決定**：視角、骨架工具、角色取得方式、美術基調。這些不需要寫程式，可以並行。
3. 第三級用**垂直切片**進入：2 名代表角色、一套骨架與 6 個最常見的動作（站、蹲、臥、走、射擊、倒地）、2 張頭像，放進固定遭遇播一場。
4. 切片的判斷標準：
   - 理解度測試沒有下降（[interface.md §4](interface.md#4-呈現路線之後) 的 80%）；
   - 測試者記得角色的名字與發生在他身上的事；
   - 資產的實際成本與時間在可接受範圍。
   三項都過，再擴大到全部動作、零件與地標；不過就停在第二級，第二級本身就是完整的產品畫面。
