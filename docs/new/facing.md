# 面向細分（設計草案）

狀態：**已實作**（`engine/tactical/facing.py`，現況以 [tactical.md §4](../tactical.md#4-人體姿勢移動) 為準）。和下面原本的構想不同的地方：
選了 0～359 的整數度數；**存的仍是向量**（那個角度查表得到的單位向量），不是角度數字——這樣所有把面向當方向用的程式都不用改，
快取鍵仍然有限、結果仍然確定，舊存檔與前端協定（`facing` 仍是 [x, y]）也不用轉換；`hug_base` 改成看最接近的上下左右（快取鍵也用它）。
身體方塊（彈道命中、可見部位）取最接近的 45°：全部用精確角度時，身體與視線快取的命中率下降，120 人交火慢了約 60%；視野、前後判斷仍用精確角度。轉身時間沒做。
這份文件整理把個體面向從 4／8 方向改成細分角度的做法；移動維持格子。
現有的系統以 [tactical.md](../tactical.md) 為準；本文提到的檔案位置是寫這份文件時（`web_v3`，`410a1ef`）的狀況。
相關：[terrain.md](terrain.md)（地形高低差與工事，可以同一輪調平衡）。

## 1. 現在的程式

- 面向是整數向量 `Unit.facing = (dx, dy)`（`engine/tactical/units.py`）。
- **轉向目標**用 `TacMap.facing_to`（`engine/tactical/tmap.py`），只回傳**東南西北 4 個方向**；設定的地方：`engine/tactical/timeline.py`（指定 `face` 時）、`engine/tactical/sim.py`（轉向最近威脅、架槍）。
- **移動**時把位移夾到 ±1（`timeline.py`），變成 8 個方向。
- 底層數學本來就支援任意角度：身體方塊（`engine/tactical/body.py` 的 `_facing_axes` 先正規化）、視野（`sim.py` 的 `fov_factor` 用 cos 夾角）、架槍方向 `braced` 與警戒扇區 `watch` 本來就是浮點向量。
- 身體方塊的快取以 `(位置, 姿勢, 面向)` 為鍵（`body.parts_cached`、`bounds_cached`、`sample_points`）。

## 2. 問題

- **視野**：敵人在 30° 方向時，面向被吸到正北或正東，最多偏 45°；本來在正面視野（±60°，係數 1.0）的敵人可能被算成側面（係數 0.5）（[tactical.md §5.1](../tactical.md#51-發現)）。
- **身體方塊**：瞄準斜前方的人，身體方塊卻正對北方，子彈看到的是錯的側面輪廓。
- **貼掩體**：`hug_base` 依上下左右挑格子的哪一邊，斜向的敵人只能挑到其中一邊。

## 3. 做法

### 3.1 面向：量化成整數角度

- 不存浮點數，存**整數角度**（候選：32 方向、每 11.25° 一個；或 0～359 度，見 §5）。
- 理由：
  - **快取**：身體方塊的快取鍵照樣有效（角度種類有限）。
  - **確定性**：整數沒有浮點誤差，存讀、規劃工作行程之間結果一致。
  - **載具**：之後的車頭方向用同一套。

### 3.2 要改的地方

- `facing_to` 回傳最接近的整數角度；`timeline.py`、`sim.py` 設定面向的地方跟著改。
- 面向與移動方向的夾角（側移 ×0.75、倒退 ×0.5，[tactical.md §4](../tactical.md#4-人體姿勢移動)）改用角度差算。
- `hug_base` 改成依面向的內積挑最接近的掩體邊（和 [terrain.md §4.3](terrain.md#43-和樓層方塊的關係) 的「土堤也算掩體」一起改）。
- `engine/tactical/worldmap.py` 布陣用的 `[0, -1]` 等改成角度。
- 存檔：舊的 `(dx, dy)` 讀進來時換成角度。
- 前端協定：面向改送角度；前端本來就有平滑轉向（`web/tac/src/tracks.ts`）。

### 3.3 轉身時間（之後再考慮）

現在轉身是瞬間的。加上轉身速度（例如 0.5 秒轉 180°）後，從背後偷襲才真的來不及反應；但 AI 會更複雜，第一版不做。

### 3.4 移動：維持格子

真正 360° 的連續移動等於離開格子，尋路、一格一人的佔用、`step_cost`、每格一個移動事件、站位搜尋、前端軌跡格式都要重寫，比縮小格子還大，**不做**。

想讓路線不要一格一格轉：

- **前端**：路線拉直、曲線平滑（已有轉角圓滑），模擬不動、結果不變。
- **之後需要再說**：引擎端路徑拉直（看得到彼此的路徑點直接連），但人仍然一格一格佔用。

載具同樣是量化的車頭角度＋格子上移動，轉彎另算成本。
