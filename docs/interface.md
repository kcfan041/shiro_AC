# 網頁介面與呈現

網頁版（`server.py`、`web/`）的現況、資訊呈現原則，以及之後的呈現路線。
Discord 版介面已凍結，見 §7。
相關：[小隊長與 LLM](squad-llm.md)、[架構](architecture.md)。舊的完整方案在 [archive/web/](archive/web/)。

## 1. 原則

- **維持指揮官視角**：玩家下達意圖，小隊自己落實。畫面要幫玩家看懂命令怎麼被接收、解讀、執行，不是讓玩家修正每名隊員的位置。**不做單兵微操。**
- **資訊限制是玩法，不是 UI 缺陷**：畫面只呈現該指揮官當時合理取得的資訊。確認、推測、最後已知、聲音來源要有不同的視覺語彙。
- **迷霧在伺服器端過濾**：前端拿不到不該知道的東西，而不是拿到了再藏起來。GM 拿完整資料。
- **後端是權威裁判**：前端可以用更高更新率播放動畫，但不能自己決定命中、發現、傷亡、士氣或 AI 行動。
- **先可讀，再華麗**：看懂單位狀態 → 看懂命令與行動 → 看懂傷亡與轉折原因 → 節奏與情緒 → 美術品質。
- **行動理由只來自規則狀態**，不用 LLM 臨時杜撰戰鬥原因。

## 2. 現在的畫面

技術：aiohttp + 原生 JS（`app.js`、`world.js`、`events.js`、`dock.js`、`tacbridge.js`）；連續地圖的戰術圖是 `web/tac/`（TypeScript＋PixiJS），見 §3。

- **登入**：暱稱（1～16 字）＋密碼（≥4）。帳號存 `data/accounts.json`（PBKDF2），session 只在記憶體、7 天，cookie `ac_session`；也可用 `?token=` 登入連結。
- **報到處**：就任指揮官、觀戰、說明、登出。
- **指揮室**：
  - 左欄：**常駐戰術圖**（連續地圖時，§3），鏡頭跟隨選中小隊，可拖曳、滾輪縮放、🎯「跟隨」切回。左上角**迷你作戰圖**（畫出戰術圖鏡頭的範圍），點了打開**作戰圖彈窗**（選格時自動開關）。
  - 中欄：**小隊卡片**——隊員（點名字看武器、熟練度、傷勢、參戰次數、是否帶過隊）、自主等級按鈕、無線電紀錄、快捷按鈕、下令回執、
    📋 命令狀態（送出 → 隊長思考中 → 執行中 → 完成／中斷＋原因，結束的狀態顯示 2 個作戰 tick）、🚑 請求後送（有人倒地才顯示）、📻 友軍無線電、📦 請求補給、🗺 戰術畫面、提議「同意」、自主行動「取消」、帶著傷員的標示。
  - 右欄：即時戰況與事件、副官、任務。
  - 作戰圖點格子：格子資訊、🛩 派無人機偵察、🤝 請求友軍支援、哪支友軍正在支援這格。
  - 戰術圖下方是**戰鬥紀錄**：影格開始播時才寫進去（和畫面同步），前面標戰鬥時間（m:ss），每秒最多重畫一次；同一人 2.5 秒內的壓制射擊（兩波）只列一筆，「射線上有隊友」5 秒內只列一次。
  - 標定與支援的快捷鍵：1 集結、2 包抄、3 集火、4 空投、5 煙幕、6 無人機、Esc 取消；選了工具會在游標處預覽範圍。
  - **回放**：每場交戰存回放（最近 20 場；連續地圖依交火的地方分段，交火一直沒停時每 2 分鐘存一段），在戰術畫面內播放，附時間軸標記與戰後摘要（§3.7）。
  - 說明、GM 都是彈窗。GM：推進 tick、暫停、補預備兵池、重置、清空、切斷／恢復通訊、看某格真相（戰術圖搬到彈窗、看得到全部）、觀戰。
  - 頂部列：GM 關掉背景 tick 顯示「（暫停）」；沒有指揮官或 GM 在線而自動暫停時顯示「（沒有玩家在線，暫停）」（只有觀戰者看得到，玩家一連上就恢復）。
- **數據鏈**：通訊正常時自己小隊即時更新；失聯時停在最後資料（「📵 失聯｜T 的資料」），快捷按鈕停用。
- **時間變慢**：伺服器模擬跟不上時（降級 AI 後仍不夠），遊戲時間整體變慢，頂部列顯示「⏱ 時間 ×0.8」（近 10 秒平均，低於 0.95 才顯示）。
- **推送**：每個執行步（0.5 秒）推無線電與戰術影格；每個作戰 tick（5 秒）推完整狀態；有事件時另外推。客戶端每 25 秒 ping，伺服器心跳 30 秒。
- **單格模式**（`zone_mode` 關閉）：戰術畫面仍是舊的 Canvas（`app.js` 的播放佇列與 `events.js` 的繪圖），不支援新畫面。播放是延後一個更新、每格長度跟著實際收到影格的間隔走，回放每格長度＝涵蓋的戰鬥時間 ÷ 播放速度。
- 設定 `setting/web.json`：`host`、`port`、`gm`（GM 暱稱）、`starter_cards`、`max_commanders`、`tick_seconds`（5）、`tac_steps`（10，一步 0.5 秒）、`react_gap`（2）、`llm_max_per_minute`、`adjutant_min_interval`、`save_path`、`replays`、`accounts`、`zone_mode`、`allies`、`background`、`autostart_tick`、`threaded`（戰術層在專用執行緒）、`plan_workers`（平行規劃行程數）、`plan_budget`（規劃時間預算）、`idle_pause_s`（沒有玩家在線多久自動暫停）。

## 3. 戰術圖（連續地圖）

目標：**流暢**（移動、轉向、姿勢、鏡頭連續，播放速度不因伺服器抖動忽快忽慢）、**看得懂**（不看圖例也分得出敵我與情報確定程度，看得出小隊在執行什麼、命令執行到哪）、**有交火的感覺**（火光、曳光、彈著、爆炸、空間化聲音）、**看得到自己的視野**、**不漏重要的事**。
視覺全部用程式畫，沒有美術資產；角色美術、頭像、配樂（第三級）的評估見 [archive/tactical-renderer-plan.md](archive/tactical-renderer-plan.md) 乙。

### 3.1 架構與建置

- 原始碼 `web/tac/`（TypeScript＋PixiJS 8 WebGL＋Vite，測試 Vitest），`python scripts/build_web.py` 建置到 `web/static/dist/`（不進 git，aiohttp 的 `/static/` 直接提供；伺服器執行時不跑 Node）。版本固定在 `web/tac/package.json`。
- 伺服器的狀態帶 `renderer`：連續地圖是 `pixi`；找不到 `dist/tac.js` 是 `missing`（戰術圖顯示怎麼建置、log 提示；開著伺服器再建置，下一次狀態就改成 `pixi`）；單格模式是 `canvas`。瀏覽器載入失敗也顯示提示。
- `src/view.ts` 的 `TacView` 是戰術圖本體（畫布、圖層、時鐘、軌跡、相機、輸入、注意力、HUD、音效、自動畫質、回放）；`src/index.ts` 建置成 `dist/tac.js`，提供 `window.Tac`（`mount`、`pushWorld`、`reset`、`follow`、`lookAt`、`zoomBy`、`setZoom`、`setTool`、`select`、`setTick`、`camera`、`playReplay`、`replaySeek`、`aar`、`on`…）。
- 舊前端用 `web/static/tacbridge.js` 接上：開圖與換視角（GM 真相、觀戰、回到即時）時重新開始播放、推送、點選隊員、工具放置（回到 `/api/mark`、`/api/support`）、跟隨、縮放、迷你圖視窗框、戰鬥紀錄、回放控制。`world.js` 只管載入地形、開圖、收推送與工具列。
- 純邏輯（時鐘、軌跡、特效與聲音排程、注意力、意圖標籤、戰後摘要）不依賴 Pixi，用 Vitest 測（`web/tac/test/`，`run_tests.py` 有 Node 時一併跑）。
- 原則：renderer 不解析業務規則、不推測未知敵人的位置；只畫伺服器已經依迷霧過濾的資料（§4）。

### 3.2 播放

- **單一戰鬥時鐘**（`clock.ts`）：整個畫面一個「播到的戰鬥時間」，目標是落後最新影格 0.75 秒。速度＝伺服器推進速度（最近 20 秒的最小平方斜率，和 1 差不到 4% 就當 1）×（1＋0.15×緩衝誤差，限 ±10%），緩衝用 3 秒平滑。開播前先存滿；見底時停住、不倒退；落後超過 3 秒（背景分頁、斷線）直接跳過並重估速度，跳過的傷亡、命令結果照樣進注意力與戰鬥紀錄。
- **個體軌跡**（`tracks.ts`）：每人一格一段（起步、抵達時間），跨影格接起來；起步停下 0.15 秒加減速、連續走時等速；連續轉彎時轉角前後各 0.35 格走曲線（轉角與內側對角格都能站才做）。
  影格結束時正在走向的下一格先當暫定，見底時照它走完；實際影格到了才換掉，位置變了 0.2 秒滑過去。重新被發現、整批換位置在那一格影格開始時才移（不提早瞬移）；一步超過 2 格的壞路徑點截斷。
- 轉向（0.15 秒、最短方向）照每格面向（`pf`）與瞄準事件；姿勢、倒地 0.25 秒過渡，時間照事件；出現 0.2 秒淡入、失去目標與陣亡淡出。投擲物落地時間照爆炸事件修正。
- **相機**（`camera.ts`）：跟隨與縮放依實際經過時間緩動（跟更新率無關），滾輪以游標為中心縮放，平移對齊整數像素；拖曳取消跟隨，🎯 回到跟隨。

### 3.3 視覺

色調是灰藍戰術圖（`src/theme.ts`；綠色版留作選項）。縮放分三個級距（`render/units.ts`；地形的烘焙級距在 `src/lod.ts`）：**戰況**（每格 < 6 px：每小隊一個人數標牌、意圖箭頭）、**小隊**（6～16：個體符號、名字、曳光）、**個體**（≥ 16：機兵剪影、小格格線、行動理由、瞄準細節）。

- **地形**（`render/terrain.ts`）：地面層（柏油路、鋪面、水泥、泥土碎石、草地，後端 `mapgen.ground_at`）加雜訊、路緣與車道虛線、室內地板；相鄰的牆連成一道、朝外的邊有亮邊與牆面、光從西北來的陰影；窗門與矮牆依走向；瓦礫；植被分地上與樹冠（在個體上面）。每個作戰格一塊，依縮放分 8／16／32 px 烘焙，高級距只烘看得到的塊。
- **個體**（`render/units.ts`）：陣營同時用形狀與顏色區分（我方綠圓、友軍青圓角方、殘部虛線圓、敵人紅菱形），灰階也分得出來。機兵剪影的肩甲與槍長依陣營與武器，走路擺動、開槍後座、架槍兩腳架、瞄準時舉槍。狀態：被壓制、釘死、光學過載、倒地紅十字（穩定後白十字）、2 樓以上白框＋「2F」、最後已知位置（虛線菱形＋秒數）。名字依序放、重疊就不放。
- **特效**（`render/fx.ts`、`fxplan.ts`）：同一次射擊（點放、壓制一波）的每一發規則上同時結算、時間一樣，畫面依第幾發（`shots[].r`）照武器射速錯開（`fxplan.ROUND_GAP`：機槍 0.075 秒、步槍 0.17、射手步槍 0.35、霰彈槍 0.6；壓制射擊每個間隔再隨機 ±`SUPP_JITTER`（步槍 40%、射手步槍 30%、霰彈槍 25%、機槍 15%），由射擊的 aid 與第幾發決定，回放每次一樣；同一發霰彈的彈丸同時；舊影格依順序推），槍舉到最後一發之後才放下。槍口火光並照亮附近地面、曳光每秒 75 格（連發每 2 發畫 1 條；警戒青、看不到的射手偏紅、壓制淡而細）；依彈著材質（`shots[].mat`）往射手方向噴塵土、碎屑、火花、血點；手榴彈拋物線與影子；爆炸閃光、衝擊環、碎屑、煙、焦痕 60 秒；閃光彈白閃；煙霧依伺服器淡入淡出；我方附近的爆炸才畫面震動（可關）。粒子分三池共 3000，背景分頁不產生。
- **視野遮罩**（`render/vision.ts`）：伺服器送的我方與友軍視野多邊形（§4）合起來，60 m 內完全清楚、之外到邊緣半亮、外面調暗；每秒一份，0.5 秒淡入淡出。和偵測同一套視線，但**視野內不代表一定會發現**（偵測還看姿勢、距離、壓制）。
- **小隊意圖層**（`render/intent.ts`、`intentplan.ts`）：小隊旁「呼號＋戰術」；推進與行軍的目標虛線、包抄弧形箭頭、撤退箭頭、集火準星、破門房間框；交互掩護時前進組腳下一圈、掩護組淡扇形；命令狀態標籤（送出、思考中、執行中一直顯示，完成、中斷、拒絕顯示 2 個作戰 tick）。友軍畫淡。
- **其他**（`render/overlay.ts`）：活動區域外調暗、交戰格邊框呼吸、作戰層情報（越舊越淡）、標定點（旗、包抄箭頭、集火準星，虛線連到小隊）、支援（預告準星＋倒數環、空投降落傘、無人機掃描圈、落地的箱子）、工具放置預覽、畫面外事件的邊緣箭頭。

### 3.4 音效

`src/audio.ts`（Web Audio）：槍聲依陣營與武器、槍的機械聲、爆炸、閃光彈、四種彈著聲、無線電提示、我方倒地警示、環境底噪。
`web/tac/public/sounds/sounds.json` 有列的用錄音，其他用程式合成；錄音的來源與授權見同目錄的 `README.md`。

- **分得出槍種與陣營**，靠三件事：
  - **節奏**：同一次射擊的每一發照 `ROUND_GAP` 錯開（§3.3），機槍「噠噠噠」最快、步槍「砰、砰、砰」、射手步槍最慢。
  - **錄音**（CC0 靶場錄音，各取一發）：我方、友軍、殘部一套（步槍 AR-15、機槍是同一把降調 15%、射手步槍 Tikka T3 .30-06、霰彈槍 Benelli Nova），敵人一套（步槍 AK-47、機槍是同一把降調 15%、射手步槍 Mosin Nagant、霰彈槍 Winchester Model 12）。沒有錄音的組合用合成音。
  - **機械聲**：霰彈槍每發後 0.15 秒泵動（Model 12 錄音裡的拉、推兩聲）、射手步槍每發後 0.45 秒彈殼落地（合成的一下短而悶的金屬聲）；音量約槍聲的 1/6、衰減得比槍聲快，是近處才隱約聽得到的背景細節，不當主要線索。
- 手榴彈爆炸是 CC0 的 mechanical explosion（音量約槍聲的 1.1 倍、5 kHz 以上收掉，原本太吵）；彈著、閃光彈、無線電、警示、環境底噪是合成音。
- 以鏡頭中心為聽者：音量隨距離衰減、遠處低通、照聲速延遲（最多 0.6 秒）、左右聲道；槍聲與機械聲的音高隨機 ±2%。
- 同時 12 個聲音（彈著與機械聲只用一半、讓給槍聲）；同一射手 0.05 秒內合併（同一發的霰彈彈丸）。
- 看不到的射手：聲音從「聽到槍聲」的誤差位置來；**聽得出槍種**（伺服器給 `shots[].wpn`），陣營當敵人；戰鬥紀錄寫「看不到的敵人（聽起來是機槍）」。
- 預設靜音，左下 🔇 打開（瀏覽器規定要先互動）；背景分頁暫停；分類音量存在瀏覽器。
- **試聽頁** `/static/dist/sound.html`（伺服器開著就能開，不用登入）：每種陣營與槍的單發、點放、壓制一輪、40 格外、看不到的射手，連續比較與一段交火範例，和遊戲同一套引擎。

### 3.5 注意力與 HUD

- **注意力**（`src/attention.ts`）：接敵（算在離被發現者最近的我方小隊，安靜 20 秒後才再提示）、我方倒地或陣亡、命令中斷、支援到達 → 右上提示卡（最多 4 張、6 秒收起），點了鏡頭移過去；依事件編號去重。上方是交火格按鈕，點了切過去；不自動搶鏡頭。
- **HUD**（`src/hud.ts`，疊在畫布上的 HTML）：懸停說明（名字、陣營、姿勢或倒地、被壓制、樓層、行動理由）、圖層開關（視野、意圖、震動）、聲音、圖例（?）、畫質（自動、固定高、固定低）、F3 診斷、到下一個作戰 tick 的時間列、畫面落後超過 1.5 秒時顯示「落後 N 秒」。
- **自動畫質**：實際幀率低於 50 持續 3 秒 → 解析度降到 DPR 1、粒子與煙霧減半；58 以上持續 10 秒再升回來。

### 3.6 效能

- 預算：一般筆電內顯、1920×1080，120 個個體交火中維持 55 fps 以上；每幀 JS ≤ 4 ms。
- 實測（無頭 Edge，RTX 5070 Ti）：120／300 人、三種縮放都 60 fps，每幀 JS 最多約 0.7 ms；成本幾乎都在像素填充。軟體繪圖（不用顯示卡）高解析度 10～16 fps，所以有自動畫質。
- 播放：抖動 ±200 ms 時播放／戰鬥 0.994、不卡住，單幀最大位移 < 0.2 格；伺服器 ×0.8 時跟著 0.8。
- 工具：`scripts/tac_bench.py`（`--soft` 軟體繪圖、`--play` 播放時鐘）、`scripts/tac_shot.py`（截圖，`--hq` 開示範伺服器的指揮室）、實驗頁 `dist/lab.html`（見 [architecture.md §8](architecture.md#8-測試與工具)）。

### 3.7 回放與戰後摘要

- 同一個畫面、同一套時鐘（回放模式：速度＝播放速度，0.25／0.5／1／2／4 倍）、同一套特效與音效；開始時鏡頭對準這場的範圍。
- 時間軸可拖曳，逐步一次 0.5 秒；鍵盤空白鍵播放／暫停、← → 前後 0.5 秒。跳到某個時間時軌跡從頭重建、戰鬥紀錄重寫到那裡。
- 時間軸上方標出倒地、陣亡（紅）、救援（綠）、支援（藍）、戰術改變、爆炸（琥珀、較短）的時間點，懸停看內容，點了跳到前 1 秒、鏡頭移過去。
- **戰後摘要**（`src/aar.ts`）：統計（開火、命中、倒地、陣亡、手榴彈、支援）與重點列表：誰被誰打倒（看不到的射手寫「看不到的射手」）、誰陣亡、誰替誰止血、誰把誰拖往掩護、支援、小隊換戰術（例如「Alpha：行軍 → 固守」）；太多時先留陣亡、倒地。每一條都能點了跳過去。只用回放裡已經依觀看者過濾的資料。
- 舊回放沒有視野、意圖等資料時，對應的層不顯示。

### 3.8 還沒驗證的

- 一般筆電內顯（目標裝置）沒有實測；自動畫質在這台不會觸發，只確認了邏輯。
- 槍聲與爆炸的錄音、其餘的合成音實際在遊戲裡聽起來怎樣（音量平衡、遠近、連發）還沒人聽過。
- §5 的理解度測試（不看說明答對 80%）還沒做；實際玩一輪的手感還沒有指揮官試過。

## 4. 結構化事件與迷霧過濾

戰鬥時記錄結構化事件，經伺服器依情報過濾後送前端（`engine/replay.py`、`engine/views.py`）：

```json
{"seq": 812, "t": 31, "phase": "fire", "sub": 0, "type": "shot",
 "actor": "s1.alpha.2", "target": "e3", "aid": "a31.7", "grp": "t31-fire",
 "data": {"mode": "suppress", "ow": false, "rounds": 4, "weapon": "dmr",
          "frm": [52.3, 40.1], "to": [[60.2, 47.9]], "impact": ["cover"]}}
```

- `seq`：整場遞增。`t`：執行步。`ts`：事件的戰鬥時間（秒，對齊 0.05 秒；第 11 步前端依此播放）。`phase`：`pre`／`move`／`overwatch`／`post_move`／`fire`／`throw`／`care`／`end`／`support`；`sub`：移動小步。
- `aid`：因果 ID，串起射擊 → 命中 → 倒地／陣亡。`grp`：同時結算群組（同一時刻的射擊 `t<n>-fire<毫秒>`、只有警戒射擊時 `t<n>-ow<毫秒>`、爆炸 `t<n>-throw<毫秒>`），播放時不能暗示不存在的先後。
- 類型：`shot hit down kia suppress spot hear lost throw blast dazzled melee brace hold_fire flanked aid drag exit surrender transfer support posture`。
- 影格另外帶 `units[].why`（行動理由）、`supp`、`bracing`、`psub`、`z`（腳下的絕對高度 m，省略＝0），以及 `shots[].aid/ow/mode/mat/r`（`r` 這次射擊的第幾發，0 不送，只給畫面錯開用；`mat` 彈著材質，只給畫面用：wall 牆／窗台、low 矮牆、rubble 瓦礫、ground 地面、body 人、air 沒打到東西、unk 不明）。
- 全圖地形 `/api/world_terrain` 另帶 `relief`：地形高低差，只列不是 0 的（`ground` [x, y, 高度]、`berm` [x, y, "E"|"N", 高度, 材質]，高度單位 `step` 0.2 m）；地圖有自然地形（[tactical.md §3](tactical.md#3-碰撞幾何)），前端還沒畫。

迷霧過濾：

- 看不到的敵人：行動者和目標 ID 拿掉；射擊只留彈道後三分之一、不給射手，但保留槍種（事件的 `weapon`、影格子彈的 `wpn`：聽得出是什麼槍）；看不到的人被命中、倒地、陣亡、架槍、換姿勢都不送。
- 呈現資料（只給畫面用，§3）：
  - 瞄準事件 `aim`（開始時間、預計開火時間 `fire`、瞄準的格子 `at`）：看不到的人的瞄準不送，瞄準看不到的人不給 `at`。
  - 影格 `units[].pf`：路徑每格走的時候的面向。
  - 影格 `vision`：我方與友軍每個人的視野多邊形，每秒一次（`engine/vision.py`，和偵測同一套視線與眼高，最遠 90 m，煙霧讓可見程度降到一半就停）；只給我方與友軍的。
  - 影格 `intents`：自己與友軍小隊的戰術意圖（種類、目標、包抄方向、集火點、破門房間、撤退方向、這一刻誰在移動誰在掩護）；敵方的不記。
  - 命令狀態（`engine/orders.py`：送出 → 隊長思考中 → 執行中／拒絕／無法對應… → 完成／中斷＋原因）：放在 `intents[].order` 與小隊卡片資料的 `order`，只給下令的指揮官。
- 打中看不到的人：影格子彈的命中對象拿掉、`kind` 改成 unknown、`mat` 改成 unk；射擊事件的 `impact` 裡的 body 改成 unknown（不然「打在人身上」會洩漏他的位置）。
- 聽到槍聲：只送引擎寫進情報的誤差位置。
- 敵方的情報事件、敵人的 `why` 與 `supp`、別人的支援都不送（煙幕都送）。
- 需要連線中的小隊才有即時資料。

## 5. 呈現路線（之後）

Phase 0（固定遭遇與基線）、Phase E（結構化事件、行動理由、迷霧過濾、前端戰鬥紀錄）、戰術地圖重做（§3：單一戰鬥時鐘、程式化視覺、音效、我方視野、小隊意圖層、命令生命週期、注意力、回放與戰後摘要）已完成。接下來的方向，**每一步都要先有實測證據再做**：

1. **驗收戰術圖**：用固定遭遇做下面的理解度測試；目標裝置（內顯）實測；實際聽音效、調音量平衡。
2. **戰術垂直切片**：用一場代表性遭遇（四人小隊、兩入口建築、2～3 守軍、包抄或破門、一次煙幕或閃光、至少一人倒地、有急救或撤退、隊長有回報）檢查整場播放是否都看得懂，補缺的呈現。
3. **角色呈現與產品化**（§6）、重連與校正、Playwright 流程測試。
4. 之後才是內容擴張：功能不同的小隊、區域控制與補給線、任務後果、教學。

**資訊層級**：預設只顯示戰況（接敵方向、交火區、傷亡）與小隊（意圖、路線、命令狀態）兩層；個體（姿勢、壓制、傷勢、理由）和細節（射線、彈著）透過選取、暫停、回放看。

**音效優先序**：無線電與接令 → 槍聲爆炸（依距離方向）→ 壓制受傷急救 → 環境 → UI → 音樂。音效精度不能超過情報精度。

**Unity**：只在產品確定需要完整 3D、多樓層、載具或下載式平台，**而且**網頁垂直切片做不到時，才做讀同一份回放的對照原型。不先重寫模擬。

驗收：測試者看完固定遭遇，不看說明能答對主要問題 80%（敵人從哪開火、第一名傷員怎麼倒的、誰在掩護誰在動、煙幕擋了誰、最近一道命令執行了沒）。

## 6. 角色呈現（Phase 4，沒有固定美術能力的前提）

- 角色層建立在戰場可讀性之上：拿掉頭像和髮色，玩家仍要看懂敵我、朝向、姿勢、武器、狀態。辨識不能只靠顏色（色覺差異）。
- 三層：**戰場小人**（可讀性優先，共用身體與動作，以髮型輪廓、主色、裝備區分）、**頭像**（存在感的主要來源，用在無線電、回執、事件、戰後報告）、**事件特寫**（後期選配，可關閉，不搶鏡頭）。
- 最小規格：4 方向的站、蹲、臥、倒地與基本移動／射擊；每名具名角色 4 張頭像（中性、緊張、受傷、堅定）。表情由可驗證狀態觸發，不由 LLM 決定。
- 資產取得順序：程式形狀佔位 → 暫用頭像驗證事件頻率 → 定 2～4 名代表角色 → 只委託代表角色的頭像 → 驗證方向數 → 定縮放後才委託戰場 sprite／骨架。
- 缺專屬資產時自動用共用模板，不阻止角色加入遊戲。
- 美術方向尚未決定的問題見 [待定問題](open-questions.md#介面與美術)。
